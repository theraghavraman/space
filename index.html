06 / Trust model

Four levels of data confidence

Useful diagnostics should report what was actually tested and what remains unverified.

LEVEL 01 / IDENTITY

Signature & extension

Check magic bytes and extension agreement. Detect common mismatches and empty/truncated files; not enough to certify a standard.

LEVEL 02 / STRUCTURE

Parser & integrity

Parse headers, records, checksums, internal references, manifests and archive members using a format-aware reader.

LEVEL 03 / COMPLIANCE

Official validator

Use versioned validators such as FITSverify and PDS Validate, or specialist libraries for SPICE, CDF, NetCDF, GRIB and GeoTIFF.

LEVEL 04 / SCIENCE

Mission context

Confirm calibration, units, coordinate systems, timestamps, product level, instrument definitions and mission-specific rules.

SECURITY / FETCH

Safe download defaults

Prefer HTTPS official endpoints, check checksums, avoid executing downloaded code, and never place access tokens in public links or client-side source.

LICENSE / REUSE

Respect upstream terms

Use official public APIs and permitted downloads. Open-source software is linked with its source/license; no third-party web app or closed code is copied wholesale.

SPACE / MISSION DATA OBSERVATORY

An independent navigation and inspection interface. It is not affiliated with or endorsed by NASA, ESA, ISRO, JAXA, CNSA, Roscosmos, CSA, NOAA or other listed organisations. Availability, API behavior, data licensing and supported formats must be verified at the source.
